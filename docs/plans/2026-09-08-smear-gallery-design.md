# 首頁抹片輪播卡 + 全螢幕螢幕保護

2026-09-08。首頁倒數卡下面一張「左圖右說明」的卡:自動十秒換一張抹片、可暫停、
可手動翻、可展開成全螢幕當螢幕保護。

## 它為什麼跟抹片練習長得相反

抹片練習的每一支端點都在防止正解外洩 —— `worker/routes/smear.ts` 的 session 那
幾支寫著「⚠️ 絕不把 `canonical_long` 或 `smear_terms` 放進這份 payload —— 那就是
答案」,全真模式交卷前的四道閘,以及 e2e 那條「整頁掃不到正解字串」。

**這張卡的整個用途就是把答案講出來。** 定位是滑手機式的被動複習,不是測驗:一眼
看到圖、旁邊就寫著這是什麼、為什麼。所以它不共用練習的任何一支端點,自己開一支
`/api/smear/gallery`,而那支的檔頭寫明**只給首頁用,任何 session / 作答路徑都不准
改用它**。兩件事因此可以並存而不互相削弱。

它也不寫任何作答紀錄:不進 `smear_answers`、不影響 `/api/smear/topic-stats`、不影響
任何統計。看了幾張圖不是「練習量」。

## 端點:一次回一批,不是一次一張

`GET /api/smear/gallery?n=24`(上限 48)。

自動十秒換一張,一張一趟的話停在首頁十分鐘就是 60 趟。而這份 payload 是純文字
(診斷名、topic、`image_note`、詳解摘要、出處),實測一批 24 筆 **20 KB** —— 同
「離線預載一年」那節量完的結論:**文字不是成本,圖片才是**。圖片仍然一張一張按需
載入,而且只預載下一張。

隨機交給 SQLite 的 `ORDER BY RANDOM()`:478 列全表掃描一趟(實測 3ms),而且
「一批之內不重複」是它免費附送的 —— client 自己抽的話得另外記已看過哪些。

詳解摘要**在 SQL 裡就從 TipTap JSON 走出來**(`json_tree` → `key='text' AND
type='text'`),沿用 migration 0016 / `lectures.ts` 書籤預覽的同一個慣用法,伺服器端
截到 220 字。整份 `content_json` 可以是幾十 KB,而卡片只畫兩三行。⚠️ 那個診斷沒有
共筆詳解時,外層純量子查詢回的是 `NULL` 不是 `''` —— shape 那一層要收掉。

**零 migration、零新表。**

**不進 `sw-guards.ts` 的 `CACHEABLE_API`**(有測試釘著)。它每次回的是一批隨機的
圖;被 SW 快取住的症狀是「每次打開首頁都是同一批」—— 而那看起來只是「怎麼老是
這幾張」,不像壞掉,所以會活很久。

## 自動輪播的四道閘

判準是純函式 `lib/smearGallery.ts` 的 `shouldAutoAdvance()`,四道閘各擋掉一種
「看起來像壞掉」:

| 閘               | 擋的是                                                    |
| ---------------- | --------------------------------------------------------- |
| `eink`           | 電子紙的殘影 + 每次換圖全屏刷新 —— 自動輪播在那上面是災難 |
| `documentHidden` | 背景分頁一路換圖、一路載圖,使用者看不到卻在燒流量         |
| `interacting`    | 正在讀說明時被換走 —— 最容易被回報成「它自己跳掉了」      |
| `hasItems`       | 空批次上跑計時器,每十秒重跑一次沒有效果的 setState        |

⚠️ **`eink` 那道閘讓暫停鈕變成一顆按了沒反應的鍵,所以那個模式下整顆不畫** ——
同 CLAUDE.md 手把那節「按下去沒反應的鍵最傷」。

暫停偏好記 `localStorage`,不進 D1:**它是裝置的屬性,不是使用者的屬性**(同
`lib/theme.ts`)。在會議室大螢幕上想讓它自己跑,在自己筆電上想按著看,兩者不該
互相覆蓋。

**計時器的相依刻意是 `state.batch` / `state.index`,不是整包 `state`。** 預抓回來
時只有 `state.next` 變,而看的還是同一張圖 —— 整包進相依的話那一張會被重新計時、
停在畫面上將近二十秒,而使用者只會覺得「有時候換得比較慢」,查不出原因。

**播完一批而下一批還沒到就原地不動,不回頭重播。** 回頭重播看起來像「同一批圖一直
循環」,使用者無從分辨那是設計還是壞掉;原地不動至少只是「停住了」,下一批一到就
自己接上。

## 全螢幕螢幕保護

**版面是自己畫的 `fixed inset-0` overlay,`requestFullscreen()` 只是順便。**
iOS Safari 不支援對非 `<video>` 元素全螢幕 —— 只靠它的話這個功能在手機上整個不
存在。overlay 在哪裡都蓋得住視窗;全螢幕 API 成功時再額外把網址列收掉。

因此 **Esc 一定要自己接**:API 沒成功時瀏覽器不會替我們處理它。反過來,使用者用
瀏覽器自己的方式離開全螢幕時要靠 `fullscreenchange` 把 overlay 一起關掉 —— 不同步
的話會留下一個蓋住整頁、看起來關不掉的黑畫面,而使用者剛按過一次 Esc,只會覺得
「按了沒反應」。

Wake Lock 是 best-effort:**會睡著的螢幕保護不是螢幕保護**。它要使用者手勢,而點下
那顆 ⛶ 就是。

### 安全區:第三種形狀

`lib/mobileChrome.test.ts` 的掃描器抓到了它,而且抓得對 —— 但 `.dialog-sheet-*`
對它是錯的工具:那兩個到 `sm` 就歸零,因為那些 sheet 在 ≥sm 會變成置中卡片。
**螢幕保護每個寬度都滿版**,而且它是唯一一個**橫著看比直著看更常見**的東西(把手機
架起來),橫向時 iPhone 的瀏海在**側邊**。

所以新增 `.screensaver-safe`,四邊都讓,並把掃描器的判準與 CSS 斷言一起擴充。
⚠️ 底色留在外層那個 `fixed inset-0`,這一層只縮內容 —— 縮到底色的話,瀏海那一圈會
露出頁面的背景,螢幕保護就框了一道白邊。

這件事的嚴重度比一般對話框高:**iOS 上那顆離開鈕是唯一的出路**(沒有鍵盤、
`requestFullscreen()` 又被拒絕),落在瀏海底下就等於出不去。

### 兩個排版上踩到的、只有看畫面才會發現的

- **控制列原本絕對定位在右上角,而它正好壓在說明的標題上** —— 離開鈕蓋住診斷名的
  最後幾個字,而那是唯一一行不能被蓋到的東西。改成放進說明欄的版面流裡,窄螢幕時
  它也順勢落到底部(拇指按得到的地方)。淡出只改 `opacity` 不改 `display`:抽掉的話
  說明會整段上跳。
- **全螢幕的說明不能沿用卡片的 `line-clamp-3`** —— 那一欄整片空著卻把說明截掉,
  是把版面的限制當成內容的限制。故 `GalleryCaption` 多一個 `clamp` prop。

### 卡片的底色

`GalleryImage` **不預設底色,由呼叫端給**。兩個用法要的不一樣:抹片是亮視野、背景
近白,卡片在亮色主題下配黑底會變成兩條重得像排版壞掉的黑帶;螢幕保護則非黑不可
(投影機或暗房)。

⚠️ **寫死一個再由 `className` 蓋是不行的**:同一層 utility 的勝負由打包後的檔案
順序決定,不是由字串裡誰寫在後面。

## 第二輪(2026-09-09):全文、橫向版面、秒數倒數

### 全螢幕畫的是共筆詳解全文

第一版全螢幕只是把 `line-clamp-3` 拿掉,但**文字本身已經被伺服器截到 220 字**,
所以照樣斷在「…」。全文平均 **1363 字**(最長 1895,103 篇共 140 KB)。

**沒有把全文放進 `/api/smear/gallery`。** 一批 24 筆會讓那支從 20 KB 漲到約
100 KB —— 每個開首頁的人都替「可能永遠不會打開的全螢幕」付這筆錢。改成進了
螢幕保護才逐張取,而且**用既有的 `/api/smear/dx/:id`**,不另開端點;結果快取在
模組層的 `Map`,輪播繞回看過的診斷就是同步命中。

⚠️ **要的是 `content_json` 而不是「更長的純文字」。** gallery 那支的摘要是
`GROUP_CONCAT` 把 TipTap JSON 壓平的結果 —— 220 字還看得下去,整篇壓平之後標題
會黏在內文裡(「…等)。 怎麼認 英文形態描述…」),愈長愈難讀。故走
`StaticContent`(`lib/staticDoc.ts`),標題、清單、表格都還在。載入中或那個診斷
沒有詳解時退回摘要,**那一區永遠不會是空的**。

⚠️ **黑底上的文字色要單獨處理,而標題必須另外點名。** `.tiptap` 是
`text-ink-800 dark:text-ink-100`,亮色主題下畫在黑底等於整段看不見。加
`.smear-note-dark` 一層只換顏色 —— **不是把 `.dark` 掛在子樹上**(那會讓底下每一處
`dark:` utility 連背景邊框一起翻面,同 `applyTheme()` 那條不變式)。而 base layer
有一條全域 `h1,h2,h3,h4 { text-ink-800 }` **直接把顏色設在標題上**,
**直接設定贏過繼承、跟 specificity 無關**,所以容器那條管不到它:實測漏掉時標題是
`rgb(26,22,15)`、內文是 `rgb(237,233,226)`,每個標題在黑底上整行看不見。

### 橫向:說明一律在下面

原本 `flex-col lg:flex-row`(≥lg 是右側欄)。改成一律 column、說明在底部,高度
`max-h-[55%]`、橫向 `landscape:max-h-[42%]` 並可捲 —— 橫向的視窗矮,說明吃太多就
沒有圖了。圖因此拿得到整個寬度。

### 秒數倒數

⚠️ **卡片持有的是「下一次換圖的時刻」(`deadlineAt`),不是剩餘秒數。** 秒數要由
那一層每秒往下數,等於每秒重繪整張卡(圖、說明、控制列);時間戳只在換圖時變一次,
而每秒變的只有 `GalleryCountdown` 裡那一個數字。`secondsLeft()` 用 `ceil`:`floor`
會讓十秒的倒數從 9 開始,看起來像少了一秒。暫停時整個不畫 —— 停著的倒數是假的資訊。

### ⚠️ portal 的事件會沿 React 樹冒泡,而那讓自動輪播在全螢幕裡一次都沒跑

第一版全螢幕開起來之後倒數整個不出現。原因不是倒數壞了:卡片那顆 `<section>` 的
`onMouseEnter` **收得到 portal 內的指標移動**(React 的 portal 事件沿 React 樹而非
DOM 樹冒泡),於是 `interacting` 永遠是 true、`shouldAutoAdvance` 永遠回 false。
畫面上唯一的線索就是倒數不見了。

修法是把兩個訊號拆開:`interacting = fullscreen ? saverReading : cardHover`。

而全螢幕那個訊號**刻意不是 hover,是說明欄的捲動位置**。螢幕保護多半是架著讓它
自己跑的,滑鼠很容易停在畫面下緣 —— 用 hover 判斷的話指標隨手一放輪播就再也不動。
捲下去過是明確的「我在讀」,回到頂端或換一張(換圖時 `scrollTop = 0`,順帶解除)
就結束。

## 程式地圖

| 檔                                            | 負責                                   |
| --------------------------------------------- | -------------------------------------- |
| `worker/routes/smear.ts` 的 `/gallery`         | SQL + 摘要截斷                         |
| `frontend/src/lib/smearGallery.ts`             | 純函式:推進、預抓時機、四道閘、偏好    |
| `frontend/src/lib/smearApi.ts`                 | `fetchSmearGallery` + `SmearGalleryItem` |
| `components/home/SmearGalleryCard.tsx`         | 卡片與所有接線(計時器、事件、狀態)     |
| `components/home/SmearGalleryParts.tsx`        | 圖與說明 —— 卡片與螢幕保護**共用**     |
| `components/home/SmearScreensaver.tsx`         | 全螢幕版面、全螢幕 API、Wake Lock、鍵盤、詳解全文取用 |
| `frontend/src/routes/Home.tsx`                 | 掛在兩個分頁**共用**的區域             |

共用的那兩塊是承重的,不是省行數:各寫一份的話,之後加一個欄位一定會有一邊漏掉,
而症狀是「全螢幕看的時候少一行」—— 沒有人會回報得清楚(同「檢討介面只有一套」)。

  空批次、四道閘各自獨立擋得住)

- `frontend/src/lib/mobileChrome.test.ts` —— `.screensaver-safe` 四邊都讓 + 掃描器
  認得第三種形狀
- `frontend/e2e/smear-gallery.test.mjs` —— 四條,**每一條都先斷言「東西找得到」再
  斷言行為**;自動輪播那條先證明它真的會動,「按了暫停就不動」才有話語權

停用驗證做過兩輪:停掉 `advance()` → 翻頁與自動輪播兩條紅、另外兩條綠;停掉
螢幕保護的 portal → 只有全螢幕那條紅。

⚠️ 過程中踩到 CLAUDE.md 已經寫著的那個坑:第一次停用驗證用了
`pnpm build > /dev/null 2>&1`,建置失敗被吞掉,測試根本沒跑就得到「全綠」。

## 沒做的

- **不記「已經看過哪些」。** 那要一張表 + 一支寫入端點,而它是隨手逛的東西 ——
  同一張圖隔幾天再出現不是 bug。
- **不做「只逛某個主題」。** 篩選是練習模式的事(`StartDialog` 已經有);這張卡的
  價值就在於不用先做任何決定。
- **不接手把。** 那一套綁定分散在 `QuestionCard` / `Question.tsx` 兩層且需要新的
  情境判斷(同抹片選項那節留下的同一塊工程)。全螢幕已經有方向鍵與空白鍵。
